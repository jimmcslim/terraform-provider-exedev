# exedev_integration Resource

Manages an exe.dev [Identity Federation](https://exe.dev/docs/integrations) (`wif`) integration. A VM the integration is attached to can mint short-lived OIDC tokens from `https://<name>.int.exe.xyz/token`, or `https://<name>.team.exe.xyz/token` for a team integration, and read `metadata` from `/metadata`. The relying party (Tailscale, AWS, GCP, Anthropic, OpenAI, …) trusts the computed `issuer` and `subject`.

## Example Usage

### Tailscale

Tailscale issues the Client ID, and with it the audience, only after it has been told the issuer and subject. Create the integration with a placeholder audience first, then set the real values. `audience` and `metadata` are updated in place and the subject does not change.

```hcl
resource "exedev_integration" "tailscale" {
  name     = "tailscale-wif"
  consumer = "tailscale"
  audience = "api.tailscale.com/${var.tailscale_client_id}" # "api.tailscale.com/pending" on the first apply
  metadata = {
    client_id = var.tailscale_client_id
    tags      = "tag:vm-exe-dev"
  }
  attach = ["tag:vm-exe-dev"]
}

output "issuer" {
  value = exedev_integration.tailscale.issuer
}

output "subject" {
  value = exedev_integration.tailscale.subject
}
```

### GCP

```hcl
resource "exedev_integration" "gcp" {
  name     = "gcpwif"
  consumer = "gcp"
  audience = "https://iam.googleapis.com/projects/${var.project_number}/locations/global/workloadIdentityPools/exe-dev-pool/providers/exe-dev"
  metadata = {
    project_id      = var.project_id
    project_number  = var.project_number
    pool_id         = "exe-dev-pool"
    provider_id     = "exe-dev"
    service_account = var.service_account_email
  }
  attach = ["vm:example-vm"]
}
```

## Argument Reference

* `name` - (Required) Integration name. It is also the VM-side hostname. Renamed in place.
* `audience` - (Required) The `aud` claim of minted tokens. Updated in place.
* `consumer` - (Optional) The relying party, such as `tailscale`, `aws`, `gcp`, `anthropic` or `openai`. Forces replacement if changed.
* `metadata` - (Optional) Map of values the VM reads from `/metadata`. Updated in place. `integrations edit` replaces the whole map, so the provider always sends every entry.
* `attach` - (Optional) Set of attachment specs: `vm:<name>`, `tag:<name>` or `auto:all`. Team integrations accept only `tag:<name>`. Updated in place with `integrations attach`/`detach`.
* `team` - (Optional) Create a team integration. Defaults to `false`. Forces replacement if changed.
* `comment` - (Optional) Free-form comment.

## Attribute Reference

* `id` - Integration name.
* `kind` - Integration type, always `wif`.
* `issuer_id` - The user- or team-scoped issuer ID.
* `issuer` - OIDC issuer URL, `https://exe.dev/issuer/<issuer_id>`.
* `subject` - The `sub` claim of minted tokens, generated by exe.dev at creation.

## Attaching to VMs

Prefer `attach` here to `exedev_vm`'s `integrations` argument. A change to `integrations` forces the VM to be replaced, whereas `attach` changes in place.

## Token Permissions

The provider token's `cmds` must include `integrations list`, `integrations add`, `integrations edit`, `integrations rename`, `integrations attach`, `integrations detach` and `integrations remove`.

## Import

Integrations can be imported by name. Prefix the name with `team/` for a team integration:

```shell
terraform import exedev_integration.tailscale tailscale-wif
terraform import exedev_integration.shared team/tailscale-wif
```
